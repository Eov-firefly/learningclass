评审对象：Eov-firefly/learningclass，提交 f0fd7d37f8f9cba4ea827a363db0f0b81798531f 中的 JANUS_v6_LaTeX.zip。

实际论文题目：Terminal-answer contracts and monitoring cost in token-limited LLM inference。

## 结论

**当前版本不建议直接投递；建议补充关键验证及复现材料后，作为范围明确的工程实证研究重新评估。** 如果按较严格的算法或系统研究期刊标准审稿，我会建议 Reject and resubmit；这不是认定论文不存在发表价值，也不是代替某家期刊作正式决定。

论文有可保留的实证贡献：把终止规则、答案解析和运行开销放到同一实验中，使用输出完全相同的 Shadow 对照测量监测开销，并公开承认历史 JANUS 实现未完成所宣称的联合调度。当前论文不能作为联合 token/compute 调度、推理能力提升或普遍加速的证据；正文已适当地收缩了这些主张。

SCI/SCIE 期刊不是统一的质量门槛。能否投稿取决于具体期刊的范围、实证要求及文章类型。本次未核实任何期刊当前的 SCIE 收录、分区或费用，不给出录用概率。

## 值得保留的设计

1. Complete 与 Shadow 输出 token ID 一致的设计，能够在所测实现中分离观察开销与生成长度变化；这是全文最有说服力的控制思想。
2. 将 contract accuracy、permissive extraction 和语义正确性区分开，避免把格式增益包装为推理增益。
3. 按问题配对；计时先平均题内重复再按问题聚类 bootstrap，没有把重复调用直接当独立问题。主要四项准确率比较也进行了多重比较控制。
4. 使用独立计时阶段，不拿双 GPU 并行主实验的延迟作为速度结论；披露预热、同步与时间边界。
5. 坦诚报告零收益、负结果、尚未完成的人工审核和历史实现问题。这些不是应被删除的“负面信息”。

## 主要审稿意见

### 1. 主终点的应用合理性尚缺关键证据

位置：2.3、3.1、4.1。

Complete 停在满足终止格式的位置；主解析器又拒绝该位置之后的非空白内容。因此观察到的优势部分来自算法与评价定义的直接匹配。这不是逻辑上无效的实验，但必须证明该定义对应真实消费者需求，而非仅制造一种会惩罚正常续写的接口。

最具体的证据是 Qwen/GSM8K：14 个增益中，13 个来自后续 LaTeX display 闭合，1 个来自代码围栏闭合。截断版本满足 marker 后仅空白的规则，却可能是未闭合文档；完整版本可能更符合人类阅读需求。不能据此推断所有 114 例都是同一种情况，但必须给出其余案例的分类。

建议提供：严格终止合同、宽松答案提取、完整 Markdown/LaTeX 结构及语义有效性下的敏感性矩阵；公开代表性配对输出，并说明该接口的具体消费场景。不要只换一个对 Complete 更有利的规则。

### 2. 对照设计能诊断故障，但不足以建立方法竞争力

位置：2.4、3.2。

Marker 在值和换行出现前就停止，0% 合同有效率几乎是定义决定的，适合作为负控制，却不能承担强基线的角色。Legacy 的 prompt token 混入候选前缀、触发后再生成一个 token 等细节也可能与其性能下降相关。Conjunction 没有保留先前完成事件，2,399/2,400 主实验输出与 Uniform 相同，主要说明当前门控几乎不起作用。

优先补充一个直接可用的边界停止基线，并对 Legacy 的索引、候选窗口和延迟应用进行定向消融。对熵条件至少比较合理的完成状态保留设计。注意：仅锁存“曾完成”并继续输出，并不保证最终返回文本仍满足终止合同；若使用缓冲、回退或截断，必须报告其额外 token 和运行成本。

无需强行复现所有推理预算算法；比较对象应与“停止回调和解析器”这一实际贡献匹配。

### 3. 科学贡献目前更接近单一实现审计，普适价值尚弱

位置：1.1、2.4、4.2。

熵观察需要计算与同步成本、终止条件需与解析规则对齐，本身并非新原理。论文主动不作这些新颖性宣称是正确的，但仍需回答：读者从本研究获得了哪些超越这套 Python callback 的新结论或可复用方法？

可将贡献聚焦为“非单调答案有效性下的终止策略评估协议”，给出明确的事件序列、状态定义、失效案例集和可运行复现工具；或者聚焦于可信的监测开销剖析。两者均需扩充相邻研究，包括边界检测、结构化输出、约束解码和低开销监测，而不是只增加引用数量。

### 4. 复现材料与稿件宣称不匹配，是当前投稿的重要障碍

位置：2.6、Data and code availability。

文章声称完成全部原始记录检查、机制一致性审计和本地重分析，但目前可见包只是排版项目。validation.json 的 passed 主要描述排版转换与文件检查，不能替代科学复现材料。

投稿前应准备匿名或正式审稿访问地址，包括协议及其时间证据、runner/parser、依赖锁定、问题 ID 与抽样清单、逐调用输出和计时、分析脚本、补充表及一键重算步骤。受许可证限制的数据可提供可重建清单，不必非法再分发。私有人类审核抽样密钥不应公开。公开时间可依具体期刊政策确定，但审稿期间需要可检查的证据，不能仅声称本地存在。

### 5. 小幅延迟效应的稳健性仍需加强

位置：2.5、2.6、3.3。

Shadow 开销为 16.46–51.18 ms，约 0.38%–1.24%；Complete 对 Qwen 两任务反而慢约 0.9%。这些数值并不支持普遍加速。作者已正确限定为实现开销，但题目层 bootstrap 无法涵盖跨会话、热状态或运行时改变引入的变异；重复同一题三次不等价于三次独立实验会话。

建议至少补充独立计时会话，保留完整执行顺序并检查时间趋势；对 callback、解析、全词表熵计算及同步做开销分解。若要作更广泛运行时或硬件结论，再补不同后端或硬件；不必为了窄范围结论穷举硬件。

### 6. 人工语义审核未完成，限制了质量主张

位置：Abstract、3.2、4.3。

人工评分不是一切格式合同研究的普遍硬性要求。若全文严格只讨论预定义接口合规性，可以选择不做人工实验，但必须证明接口合理性，不能声称更好的语义答案质量。

本稿的核心争议恰好涉及未闭合格式与完整回答何者更可用，完成已规划的双人盲评很有价值。需报告抽样层、纳入概率、原始独立评分、一致性及裁决方式；由于样本富集了不一致案例，不能用未加权均值估计总体语义正确率。不要用另一个 LLM 的自动判断替代独立人工结果后仍称“人工审核”。

### 7. 外推范围和模型任务选择不足以支持广泛 LLM 结论

位置：2.1、2.2、4.3。

只有两个约 7B 模型、两个短答案任务、一个 512-token 上限、greedy、batch size 1。对这些条件下的案例研究尚可，但无法支持一般预算分配、长推理、服务吞吐或 agent 结论。

若保持当前窄范围定位，优先做合同和机制消融；若希望面向更有竞争力的普遍系统结论，再加入多个预算点、不同模型族及至少一种更贴近结构化接口的任务。不要先盲目扩大调用量再补研究问题。

### 8. “冻结”与独立性需要可审计证据

位置：2.1、2.6、4.4。

排除历史接触的 582 道 GSM8K 问题是合理防护，但剩余 cohort 不再是完整官方测试集的随机代表；应说明可推广的目标总体。也不能据此宣称排除模型训练污染。

请公开协议哈希、提交时间、阈值选择记录、实际执行 receipt 和阶段数据访问顺序。现稿文字并不等于已核实的公开预注册，亦不能单凭材料不可见就认定存在事后选择。应明确“冻结协议”与“外部预注册”的区别。

## 投稿定位与修改优先级

### 投稿前必做

1. 提供可审查的代码、协议、逐调用结果及补充指标；独立重算主要统计。
2. 明确终止合同的应用需求，并提供格式与提取规则敏感性、114 个增益案例的错误分类。
3. 加入至少一个合理的直接边界停止对照，以及针对失效熵门控的机制消融。
4. 确认作者及所有声明，完成真实的数据/代码访问说明。
5. 按具体目标期刊核实相关文献、收录、格式和材料政策。

### 强烈建议

完成盲法语义评估及独立计时会话。若不完成人工评估，则保持纯接口合规性结论，并提供足够强的非人工合同验证。

### 取决于投稿目标

多预算、多模型、多后端、吞吐/并发实验用于扩大结论范围；若坚持窄范围实证稿，不是每项都必须补。现稿不应优先投向要求显著算法创新或广泛系统收益的高竞争力期刊。可在补齐材料后，筛选接受实证评估、软件工程或 AI 系统测量研究的计算机类期刊。PeerJ Computer Science 可作为范围核对候选，尚不能据此认定符合其最新政策或当前索引状态。
