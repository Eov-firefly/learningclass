# 可选追加实验：预算可控完成（2卡 / 4卡）

日期：2026-10-29。**代码已准备并通过CPU软件检查，尚未运行本轮真实模型实验。优先执行既有raw的CPU再分析；不要立即重跑旧6,976条。**

本目录补齐上一轮方案中尚未实现的GPU运行器，复用相邻`experiments_v89`中的已交付推理引擎，不改动原24-token主比较或根目录论文。与`controllability_v1`是两个入口：前者分析已经发生的实验，本目录生成新的、另行标记的实验记录。

## 设计及证据边界

| 项目 | 冻结规则 |
| --- | --- |
| 题目 | 默认64题；按题号哈希选取，不用答案或推理结果选题 |
| 默认数据 | 现有96道ARC评估题中的64题，明确标为**已知队列探索性实验**，不是独立新验证 |
| 可替换数据 | 同一public/scoring格式的外部64题；支持多个历史public文件排除；仅无112题重叠不足以证明从未使用 |
| 模型 | 固定revision的Qwen2.5-7B-Instruct-1M和Mistral-7B-Instruct-v0.3 |
| 输出 | 精确选项全文JSON；相同prompt、共同prefix、有限文本合同 |
| 预算1 fixed8 | 全局8-token后缀预算；依据既有探索结果选择，保留选择来源 |
| 预算2 exact_min | 每题、每模型的最短canonical接受路径长度 |
| 预算3 wide | 每题、每模型的最长canonical接受路径长度 |
| 策略 | grammar、Full、真实XGrammar、sequence_score、deterministic |
| 记录数 | 64×2×3×5 = **1,920条**，其中1,536条模型请求上限、384条确定性CPU完成 |

校准/预热另计：每worker用一道人们已知的旧dev题执行2次Full预热和15条校准记录（12条神经策略、3条确定性）。两卡共额外28次模型请求上限，四卡共56次。预算不可行时某些请求无需模型调用。

首要比较是fixed8下、相同canonical语言的**起始可行请求中Full−grammar认证完成率**，分别报告两个模型，给保守97.5%配对区间；同时报告所有请求覆盖、正确提交、错误提交、完整成本，不用条件准确率隐藏新增错误。若复用旧题，区间仍是探索性描述，不能靠先写protocol.json就变成独立确认结果。

exact_min和wide是机制压力/不活跃控制，不能冒充真实部署预算分布。各条件即使数值预算相同也保留，不按结果删题或合并成独立样本。64题只用于成本规划，不保证统计功效或正确率非劣。若要正式确认，应先完成旧raw再分析和功效评估，冻结真正的新题来源与样本量。

轨迹保持检查只针对精确同语言、同预算、同模型/greedy条件的Full与grammar。XGrammar可接受不同token化，不能用canonical trie诊断其“语法逸出”。确定性完成和候选评分也可具有预算完成保证，因此不得把共有性质写成Full独有创新。

## 并行、加速及计时

- **2张A100/A800**：GPU0跑全部Qwen，GPU1跑全部Mistral；两模型并行，各加载一次。
- **4张A100/A800**：GPU0/1各跑一半Qwen题，GPU2/3各跑一半Mistral题；每题所有策略留在同一个worker。
- 单卡单7B模型、BF16、SDPA、greedy、KV cache、batch1；不使用TP/DDP，不下载1M长度上下文，不更改模型revision。
- 模型只预取一次；冻结tokenizer路径后不下载或加载第二套权重。四卡复制同模型是分题并行，不是四卡共同推理一个请求。
- 候选评分一次合理批量评分约4个完整候选，保留其输入token/forward/时间；当前小K无需故意限制其能力。确定性对照不调用模型。
- 记录编译、失败调用和死路后调用。精确oracle/audit开启，故这些耗时是**带诊断的正确性运行**，不能直接写成无插桩部署延迟优势。若需要严格性能主张，另冻计时协议。
- 先`--calibrate-only`检查环境和粗略ETA，再正式执行；不根据校准正确率调预算。ETA由一道人们已知的dev题推算，不是置信区间，也未在本轮GPU实测。预留30–90分钟推理窗口作为宽松安排，安装/下载和完整权重hash另计；实际以服务器校准为准，四卡也不承诺恰好快一倍。
